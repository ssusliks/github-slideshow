# Архитектура

## Общая схема

```
            ┌────────────────────────── клиент (game/) ───────────────────────────┐
 данные     │  src/data      башни, рецепты, враги, уровни, усиления, экономика   │
            │       │                                                              │
 правила    │  src/core  ──► бой: волны, урон, статусы, слияния, способности      │
            │  src/meta  ──► аккаунт: награды, исследования, задания, офлайн      │
            │       │                                                              │
 сервисы    │  src/services  сохранения · облако · реклама · покупки · звук ·     │
            │                производительность · локализация · журнал ошибок     │
            │       │                                                              │
 показ      │  src/render (Three.js)        src/ui (экраны, HUD, ввод)            │
            └──────────────────────────────────┬───────────────────────────────────┘
                                               │ HTTPS (необязательно)
                                   ┌───────────▼────────────┐
                                   │ server/  аккаунты,     │
                                   │ облачные сохранения,   │
                                   │ проверка покупок       │
                                   └────────────────────────┘
```

Зависимости направлены только вниз по этой схеме: `core` и `meta` ничего не знают о графике,
интерфейсе и сети. Поэтому бой запускается без браузера — на этом построены модульные тесты и
симуляции баланса, проигрывающие тысячи боёв за секунды.

## Модули клиента

### `src/data` — игровые данные

Весь контент — таблицы, а не код:

| Файл | Содержимое |
|---|---|
| `towers.ts` | 8 базовых башен, 9 гибридов, ветки эволюции, рецепты слияния, запрещённые пары, реакции стихий, множители ступеней |
| `enemies.ts` | архетипы врагов, 4 мира по 7–8 врагов, 4 босса |
| `worlds.ts` | 6 карт (ASCII-схемы), 4 мира, 24 уровня, способности, параметры бесконечного режима |
| `boosts.ts` | 37 усилений с редкостью и условиями появления |
| `meta.ts` | карты башен, дерево исследований, задания, достижения, календарь входа, магазин, лимиты рекламы, события |

Добавить башню — добавить запись в `towers.ts`, тексты в `scripts/i18n.mjs` и (по желанию) вид
в `render/models.ts`. Правила боя менять не нужно.

### `src/core` — симуляция боя

- `battle.ts` — класс `Battle`. Фиксированный шаг 1/30 с, детерминированный генератор случайных
  чисел. Состояние `BattleState` — простые данные, которые в любой момент можно сериализовать
  и восстановить (на этом работает возобновление боя после сворачивания).
- Все действия игрока — проверяемые методы, возвращающие `{ ok }` или `{ ok: false, reason }`:
  `buyTower`, `moveTower`, `upgradeTower`, `sellTower`, `merge`, `useAbility`, `chooseBoost`, `revive`.
- `merge.ts` — правила слияния как чистая функция `checkMerge`. Слияние в `Battle.merge` атомарно:
  сначала полная проверка и расчёт результата, затем одна фиксация.
- `stats.ts` — расчёт характеристик башни; одна и та же функция используется боем, предпросмотром
  слияния и экраном коллекции.
- `waves.ts` — генератор волн: заданные группы из таблицы уровня плюс случайное наполнение по
  «бюджету угрозы».
- `map.ts` — разбор схемы карты, поиск маршрутов, проверка корректности.

Бой сообщает о происходящем очередью событий (`events`), которую читают графика и звук.
Графика никогда не меняет состояние боя.

### `src/meta` — правила аккаунта

- `profile.ts` — структура профиля, `sanitizeProfile` (приводит любые входные данные к корректному
  профилю, обрезая значения по допустимым пределам), оценка прогресса для разрешения конфликтов.
- `game.ts` — класс `Game`: единственное место, где меняется профиль. Ключевые механизмы:
  - **журнал выдач** (`grant(reward, grantId)`): любая награда применяется один раз на идентификатор —
    уровень, реклама, покупка, задание;
  - **проверка результата боя** (`finishRun`): неправдоподобный результат отклоняется и записывается в журнал;
  - **защищённые часы** (`effectiveNow`, отметка максимального виденного времени): перевод часов назад
    не даёт ни повторных ежедневных наград, ни офлайн-дохода.

### `src/services`

| Сервис | Назначение |
|---|---|
| `save.ts` | локальные сохранения с подписью HMAC-SHA256, три скользящие копии, снимки перед критическими операциями |
| `storage.ts` | хранилище ключ–значение; на устройстве дублируется в Capacitor Preferences |
| `cloud.ts` | гостевой аккаунт, регистрация, вход, привязка Google/Apple, двусторонняя синхронизация |
| `iap.ts` | покупки: журнал незавершённых транзакций, проверка, доставка, восстановление |
| `ads.ts` | вознаграждаемая реклама (AdMob; тестовый провайдер для разработки) |
| `integrity.ts` | проверка, не изменена ли сборка |
| `log.ts` | журнал ошибок, предохранители (circuit breaker), тайм-ауты, сторож зависаний |
| `perf.ts` | ограничитель кадров 30/60, адаптивное качество, защита от перегрева |
| `audio.ts` | звуки и музыка, синтезируемые через WebAudio (без аудиофайлов) |
| `i18n.ts`, `settings.ts`, `platform.ts`, `net.ts`, `hash.ts` | локализация, настройки, обёртка над Capacitor, HTTP-клиент, SHA-256 |

### `src/render` и `src/ui`

- `render/models.ts` — процедурные низкополигональные модели башен, врагов, замка, декора из
  нескольких общих примитивов и кэшируемых материалов. Игра не содержит ни одного файла графики.
- `render/view.ts` — сцена боя: ортографическая камера под фиксированным углом, пулы объектов
  для врагов, снарядов, молний, колец; единая система частиц одним вызовом отрисовки.
- `render/thumb.ts` — миниатюры башен и врагов для меню рендерятся из тех же моделей.
- `ui/app.ts` — оболочка: сервисы, единый цикл кадров, навигация, жизненный цикл приложения.
- `ui/battle.ts` — HUD, сенсорный ввод (перетаскивание, касания, щипок), обучение, результаты.
- `ui/screens.ts` — меню, карта, башни, исследования, задания, магазин, настройки.

## Сохранения и облако

**Локально.** Профиль хранится в конверте `{ savedAt, data, mac }`. Ключ подписи выводится из
секрета установки. При загрузке:

1. подпись верна → профиль принят;
2. подпись неверна или файл повреждён → берётся самая свежая корректная резервная копия;
3. копий нет, но данные читаются → профиль принимается после обрезки значений, с пометкой
   (честного игрока не обнуляем);
4. ничего не читается → новый профиль.

**Облако.** Сервер хранит профиль целиком с номером ревизии и пятью предыдущими версиями.
Синхронизация никогда не сливает два профиля по полям — это позволило бы дублировать валюту.
При конфликте побеждает один профиль целиком (по оценке прогресса), второй сохраняется как
восстановимая копия: локально (`bak.alt`) либо в истории на сервере.

**Незавершённый бой.** Журнал `run` хранит идентификатор боя и флаг `clean`:

- при сворачивании пишется `clean: true` и снимок боя → после убийства процесса системой бой
  можно продолжить;
- при возвращении на экран флаг сбрасывается → если процесс упадёт во время боя, при следующем
  запуске уровень начнётся сначала, без наград.

## Сервер (`server/`)

Node.js без сторонних зависимостей. Маршруты:

| Маршрут | Назначение |
|---|---|
| `POST /v1/auth/guest`, `register`, `login`, `oidc`, `link` | гостевой аккаунт, регистрация по почте, вход, вход и привязка Google/Apple |
| `GET/PUT /v1/save`, `GET /v1/save/history[/:rev]` | облачное сохранение с контролем версий и историей |
| `POST /v1/iap/verify` | проверка покупки в Google Play / App Store, защита от повторного использования чека |
| `POST /v1/support/ticket` | обращения в поддержку |
| `DELETE /v1/account` | удаление аккаунта и данных |
| `GET /v1/time`, `/v1/health` | серверное время, проверка работоспособности |

Пароли хешируются scrypt, токены хранятся в виде хешей, есть ограничение частоты запросов и
размера тела. Хранилище — JSON-файл с атомарной записью: этого достаточно для запуска и тестов;
для нагрузки модуль `store.mjs` нужно заменить на базу данных (см. ROADMAP).

## Решения

1. **TypeScript + Three.js + Capacitor вместо Unity.** В среде разработки нет Unity Editor и
   лицензии; проект Unity пришлось бы писать, ни разу не запустив. Выбранный стек позволил
   запускать игру, тестировать её автоматически и собрать APK. Цена: меньше готовых инструментов
   (редактор сцен, анимации), графика процедурная.
   *Путь переноса в Unity:* таблицы из `src/data` переносятся в ScriptableObject почти дословно;
   `src/core` и `src/meta` — чистая логика без зависимостей от платформы, переводится на C#
   построчно; тесты из `tests/` служат спецификацией поведения.
2. **Процедурная графика и звук.** Нет зависимости от чужих ассетов и вопросов авторских прав,
   малый размер приложения. Цена: стилизация проще, чем у нарисованной художником графики.
3. **Детерминированная симуляция, отделённая от показа.** Даёт возобновление боя, симуляции
   баланса, воспроизводимые тесты.
4. **Победа в конфликте сохранений — целиком одной стороны.** Исключает дублирование валют ценой
   возможной потери менее продвинутой ветки (она остаётся в резервной копии).
5. **Без системы Prestige и Battle Pass в первой версии.** Для Battle Pass зафиксирован формат
   сезона (`BattlePassSeason` в `data/meta.ts`), функция выключена флагом.
6. **Поддержка без сбора данных по умолчанию.** Журналы ошибок отправляются только когда игрок
   сам прикладывает их к обращению.
